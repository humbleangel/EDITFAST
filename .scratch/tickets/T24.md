## What to build

End-to-end verification that the deployed `fast_apply_edit.ts` is actually loaded by OpenCode and registered as a tool. The bug we're working around (#31354, #33455) means a silent failure is possible — we need a positive confirmation.

Steps:
1. Open a new opencode session in any test project (e.g. `C:\AI\REFERENCES\opencode-dev` or any small project)
2. Run `/tools` or `opencode debug tools` to list registered tools
3. Confirm `fast_apply_edit` appears in the list
4. In a fresh session, ask the model: `"What custom tools are available? List them all."` and verify the model sees `fast_apply_edit` in its advertised tool set
5. Optional: run a real edit by feeding the model a test file + an `original_code` + a `code_edit` and confirming the diff is produced

Document the verification commands and outputs in `docs/verification.md`.

## Acceptance criteria

- [ ] `opencode debug tools` lists `fast_apply_edit`
- [ ] The model advertises `fast_apply_edit` in its available tools when prompted
- [ ] `docs/verification.md` records the commands run and their outputs
- [ ] If verification fails: investigate, fix, retry (likely causes: typo in filename, missing `export default`, the file not being at the right path, or a regression of bugs #33455/#31354 on this specific opencode version)

## Blocked by

None — can start immediately (T23 just needs the file deployed; verification works against any deployment state).
