## What to build

The pre-flight checks and inline error messages that short-circuit the execute flow before any expensive work is done.

File: `src/checks.ts`

Exports:
- `checkFileReady(filepath: string): Promise<{ ready: true } | { ready: false; error: string }>` — uses `fs/promises.access(filepath, constants.R_OK | constants.W_OK)`. Returns ready if no throw; otherwise returns the original plugin's "File not found or not writable" message (including a hint to use `write` for new files).
- `API_KEY_MISSING_MESSAGE: string` — the API-key-missing error message: `"Error: FAST_APPLY_API_KEY not configured.\n\nTo use fast_apply_edit, set the FAST_APPLY_API_KEY environment variable.\nGet your API key at: https://openai.com/api\n\nAlternatively, use the native 'edit' tool for this change."`

The file-not-ready message structure (from the reference):
```
Error: File not found or not writable: ${target_filepath}

This tool is for EDITING EXISTING FILES ONLY.
For new file creation, use the 'write' tool instead.

Example:
write({
  filePath: "${target_filepath}",
  content: "your file content here"
})
```

Tests: `tests/checks.test.ts` — use temp directory + real files

## Acceptance criteria

- [ ] Existing readable+writable file returns `{ ready: true }`
- [ ] Non-existent file returns `{ ready: false, error: ... }`
- [ ] Read-only file (chmod 444 on POSIX, equivalent on Windows) returns `{ ready: false, error: ... }`
- [ ] Error message includes the hint about `write` tool
- [ ] `API_KEY_MISSING_MESSAGE` is the exact reference text
- [ ] `bun test tests/checks.test.ts` passes
