## What to build

End-to-end integration test that drives the full `fast_apply_edit` execute function with mocked fetch, exercising every code path in a real flow.

File: `tests/integration.test.ts`

Test scenarios:
1. **Happy path**: mock fetch returns a successful merge response → tool returns the formatted success string with `✓ Fast Apply complete`, contains the diff, and the file on disk reflects the merge
2. **API key missing**: with `process.env.FAST_APPLY_API_KEY` unset → tool returns the API_KEY_MISSING_MESSAGE
3. **File not found**: target path doesn't exist → tool returns the file-not-ready error
4. **API HTTP error**: mock fetch returns 500 → tool returns formatted error mentioning the status
5. **API parse failure**: mock fetch returns invalid XML (no `<updated-code>`) → tool returns error mentioning parse failure
6. **Cannot locate original_code**: file content doesn't include `original_code` → tool returns the multi-line "Cannot locate original_code" error
7. **Multi-occurrence**: `original_code` appears twice in the file → tool returns the "appears N times" error

Use `bun:test` with `mock.module()` or `spyOn(globalThis, "fetch")`. Use `fs.mkdtemp(os.tmpdir() + ...) + "/"` for scratch files. Clean up in `afterEach`.

## Acceptance criteria

- [ ] All 7 scenarios pass
- [ ] Real temp files are written, read, and verified on disk
- [ ] Mock fetch is reset between tests
- [ ] `bun test tests/integration.test.ts` passes
