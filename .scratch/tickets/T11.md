## What to build

The core file patching function that locates `original_code` in the current file content (with exact + normalized fallback) and replaces it with `merged_code`. Detects multi-occurrence ambiguity, binary files, and returns a structured success/failure result.

File: `src/patch.ts`

Exports:
- `applyPartialEdit(filepath: string, original_code: string, merged_code: string): Promise<{ success: true; newFileContent: string } | { success: false; error: string }>`

Logic:
1. Read the current file via `fs/promises.readFile(filepath, "utf-8")`
2. If content contains `\0`, return `{ success: false, error: "Cannot edit binary files" }`
3. Try `findExactMatch(currentFile, original_code)` (T7) — keep match type `"exact"`
4. If -1, try `findNormalizedMatch(currentFile, original_code)` (T8) — match type `"normalized"`
5. If still -1, return error with multi-line guidance: "Cannot locate original_code in <path>. The content you provided doesn't match the current file. POSSIBLE CAUSES: ... SOLUTIONS: 1. Re-read ... 2. Verify exact whitespace ... 3. Provide more context ... 4. Use native 'edit' tool for exact string matching"
6. Count occurrences of `original_code` in `currentFile` via `split(original_code).length - 1`. If > 1, return error: "original_code appears N times in <path>. Please provide more context..."
7. Build `newFileContent = currentFile.substring(0, index) + merged_code + currentFile.substring(index + original_code.length)`
8. Return `{ success: true, newFileContent }`

Reference: `tickernelz/opencode-fast-apply` `applyPartialEdit`

Tests: `tests/patch.test.ts` — use real temp files via `fs.mkdtemp` and clean up after

## Acceptance criteria

- [ ] Exact match replaces the section, preserving surrounding content
- [ ] CRLF/trimmed whitespace differs only in normalized form → normalized match succeeds and returns correct byte offset
- [ ] `original_code` not present at all → error returned
- [ ] `original_code` present twice → error returned with count
- [ ] File with `\0` byte → "Cannot edit binary files" error
- [ ] Returned `newFileContent` round-trips: writing then reading yields the same string
- [ ] `bun test tests/patch.test.ts` passes
